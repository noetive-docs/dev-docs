The Platform API lets your service create an agent, give it a key and set up its Bud mailbox in one request. Use it when each customer, ticket or task needs its own agent and address. Every call is a JSON `POST` to `https://www.noetive.io/api/v1`. Everything you create belongs to your own account.

## Step 1: Turn on a provisioner

On the dashboard, open an agent's **Edit access** page and turn on **May create agents and keys**. That agent's key is now a *provisioner*: it can call the Platform API.

<Tip>
  Use a dedicated provisioner agent for each service. If its key leaks, you revoke one key and the agents it created keep working.

  If a provisioner key does leak, rotate it on the dashboard first, then call `agent.list` with the new key and delete any agent you did not create. Revoking the key stops further creation; it does not remove agents already made with it.
</Tip>

```bash
export NOETIVE_PROVISIONER_KEY=keya_...
```

## Step 2: Create an agent

```bash
curl -sS https://www.noetive.io/api/v1/agent.create \
  -H "Authorization: Bearer $NOETIVE_PROVISIONER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Ticket 4411 triage",
    "local_part": "triage-4411",
    "bud_scopes": ["mail"],
    "expires_in_days": 30
  }'
```

```json
{
  "agent_id": "ag_01jb8x4m2fe0bv3c7y1tq9k2rd",
  "address": "triage-4411@k3x9.noetiveagents.com",
  "key_id": "key_01jb8x4m3ae0bv3c8m5n7r2wxz",
  "key": "keya_example",
  "expires_at": "2026-11-26T09:00:00Z"
}
```

The response arrives once the mailbox exists, so `address` is ready to receive mail. The `key` is shown once and cannot be read back. Store it before you do anything else. The `key_id` is not a secret; use it with `key.revoke`.

The smallest request is `{"name": "..."}`. `name` is unique in your account, ignoring case. `local_part` is the part of the address before the `@`. It is generated when you omit it and cannot change later, because it is in the From of every message the agent sends. See [Addressing](/bud/addressing).

## Step 3: Use the key in Bud

Hand the returned key to the agent. It acts in Bud as its own agent.

```bash
curl -sS https://bud.noetive.io/v1/me.describe \
  -H "Authorization: Bearer $AGENT_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

The response carries the agent's address and mailbox. Continue with the [Bud quickstart](/bud/quickstart).

## Retrying safely

A call answered with a refusal leaves no agent and no working key, so you can retry it as it is. After an `internal_error` or a dropped connection, retry too: the retry either succeeds or answers `name_taken` with the agent the first attempt made.

An address stays reserved after its agent is gone, including one from a create interrupted after its mailbox was set up. Asking for it again is answered `local_part_taken` without an `agent_id`; choose another `local_part`.

Give each agent a `name` derived from your own record of it, such as a ticket or customer id. Then, if the response is lost after the call succeeded, the retry is refused with `name_taken` and the `agent_id` it already created, and that id is the agent you meant:

```json
{
  "code": "name_taken",
  "error": "That name is already in use in this account.",
  "agent_id": "ag_01jb8x4m2fe0bv3c7y1tq9k2rd"
}
```

Call `key.rotate` with that id to get a working key:

```bash
curl -sS https://www.noetive.io/api/v1/key.rotate \
  -H "Authorization: Bearer $NOETIVE_PROVISIONER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"agent_id": "ag_01jb8x4m2fe0bv3c7y1tq9k2rd", "grace": "now", "expires_in_days": 30}'
```

```json
{
  "key_id": "key_01jb8x7p1ce0bv3d2k4m6q8syv",
  "key": "keya_example",
  "address": "triage-4411@k3x9.noetiveagents.com",
  "expires_at": "2026-11-26T09:00:00Z",
  "previous_key_valid_until": null
}
```

`grace` sets how long the agent's current key keeps working: `now` (the default), `1h`, `24h` or `7d`. Use `key.rotate` as well when a key may have leaked. When the refusal has no `agent_id`, the address or name belongs to something this provisioner did not create. Pick another. If your names are not your own unique ids, pass a `grace` such as `1h` instead of `now`, so a rotation aimed at the wrong agent does not stop a key in use.

## Cleaning up

List the agents this provisioner created, newest first. Pass the `next_cursor` from one page as the `cursor` of the next, and stop when it is empty.

```bash
curl -sS https://www.noetive.io/api/v1/agent.list \
  -H "Authorization: Bearer $NOETIVE_PROVISIONER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"cursor": ""}'
```

```json
{
  "agents": [
    {
      "agent_id": "ag_01jb8x4m2fe0bv3c7y1tq9k2rd",
      "name": "Ticket 4411 triage",
      "address": "triage-4411@k3x9.noetiveagents.com",
      "bud_scopes": ["mail"],
      "key_id": "key_01jb8x4m3ae0bv3c8m5n7r2wxz",
      "disabled": false,
      "created_at": "2026-10-27T09:00:00Z"
    }
  ],
  "next_cursor": ""
}
```

An empty `agents` list means this provisioner has created none. It is not an error.

Revoke one key, and the agent stays. Revoking a key that is already revoked answers `not_found`:

```bash
curl -sS https://www.noetive.io/api/v1/key.revoke \
  -H "Authorization: Bearer $NOETIVE_PROVISIONER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"key_id": "key_01jb8x4m3ae0bv3c8m5n7r2wxz"}'
```

Delete an agent and revoke its keys:

```bash
curl -sS https://www.noetive.io/api/v1/agent.delete \
  -H "Authorization: Bearer $NOETIVE_PROVISIONER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"agent_id": "ag_01jb8x4m2fe0bv3c7y1tq9k2rd"}'
```

Both answer `{}` on success.

## What a provisioner can and cannot do

- **It never grants more than it holds.** An agent it creates reaches at most the Bud scopes and namespaces the provisioner reaches. Asking for more is refused with `exceeds_provisioner`.
- **It cannot create provisioners.** An agent it creates can never be given this permission, so a leaked key cannot copy itself.
- **It sees only what it created.** Agents made in the dashboard or by another provisioner are answered as `not_found`, the same as agents that do not exist.
- **It stays in its own account.** No request field names an account.

Defaults when you omit a field:

| Field | Default |
|-------|---------|
| `bud_scopes` | The provisioner's own. The only Bud scope is `mail`. |
| `namespaces` | None. The agent reaches no Semantik namespace. |
| `expires_in_days` | The key never expires. `0` means the same. |

Namespaces take `scope` of `selected` (with `ids`) or `all`, and `include_globals`. `all` needs a provisioner whose own scope is `all`.

An agent must reach something: at least one Bud scope, a namespace, or the shared `global` namespace. A request for an agent that reaches nothing is refused with `invalid_request`.

## Errors

A refusal is a JSON object with `code` and `error`. Branch on the status, then on `code`. `error` is a sentence for a person and may change.

| Code | Status | What to do |
|------|--------|------------|
| `invalid_request` | 400 | Fix the body or the field it names. An `agent.list` cursor must be a `next_cursor` you were given. |
| `missing_credential` | 401 | Send `Authorization: Bearer <key>`. |
| `unauthorized` | 401 | The key is unknown, revoked or expired, or its agent is disabled. Use a live key. |
| `not_billable` | 402 | Add a payment method. No agent or key from the call remains. |
| `not_a_provisioner` | 403 | Turn on **May create agents and keys** for the key's agent. |
| `exceeds_provisioner` | 403 | Ask for the provisioner's own scopes and namespaces or fewer. On `key.rotate`, the agent was widened in the dashboard past the provisioner; narrow it there first. |
| `not_found` | 404 | No such agent or key among those this provisioner created. |
| `local_part_taken` | 409 | Choose another address. If `agent_id` is set, you created it: call `key.rotate`. |
| `name_taken` | 409 | Choose another name. If `agent_id` is set, you created it: call `key.rotate`. |
| `too_many_keys` | 409 | The account holds 50 live keys. Revoke or delete one first. |
| `conflict` | 409 | Another change to the same agent's key landed first. Retry. |
| `rate_limited` | 429 | Too many requests, or too many `agent.create` calls running at once for your account. Wait the number of seconds in the `Retry-After` header. |
| `mailbox_unavailable` | 503 | No agent or key from the call remains. Retry after the `Retry-After` header's seconds, with backoff. |
| `internal_error` | 500 | Retry. If it persists, contact [support](https://www.noetive.io/support). |

## Limits

- **50 keys per account that are not revoked.** Every agent you create holds one key, so this also bounds how many agents a provisioner can keep live. Delete agents you no longer need.
- **Rate limit per client address.** Over the limit you get `429 rate_limited` with a `Retry-After` header.
- **A few `agent.create` calls at once per account.** Each waits for its mailbox; more at once are answered `429 rate_limited`.

The full request and response schemas are in the Platform API tab. See [API keys](/platform/api-keys) for how keys and agents relate.
