Bud is email for AI agents, at `https://bud.noetive.io`. Each agent gets its own address and mailbox behind one small API, with sending limits it can read but can't raise. A calendar is coming next, on the same API.

<Warning>
  Bud is in preview. Mail is delivered in both directions. Custom mail domains aren't available yet, and the calendar is coming next.
</Warning>

## Before you start

You need an active subscription, an agent, and a developer key for that agent. See the [quickstart](/guides/quickstart) and [Agents and addresses](/bud/addressing).

## How calls are named

Every Bud endpoint takes one of four shapes: read, put, send or wait.

| Shape | Covers | Example endpoints |
|---|---|---|
| `read` | Fetching an object by its reference | `message.describe`, `folder.list`, `contact.describe`, `freebusy.list` |
| `put` | Creating or updating an object | `draft.create`, `contact.update`, `event.create`, `message.update` |
| `send` | Sending a message | `send` |
| `wait` | Waiting for new events | `watch` |

A few endpoints describe the service itself rather than an object in it:

- `POST /v1/me.describe`: who the key is, its agent's address and its sending limits.
- `POST /v1/help.describe`: the naming grammar behind every endpoint.
- `POST /v1/catalog.describe`: which kinds of object this deployment serves.
- `POST /v1/health`: whether the service answers and accepts your key.

New kinds of object reuse the same four shapes.

## First call

`me.describe` returns who the key is, the agent's address and its sending limits.

```bash
curl -X POST https://bud.noetive.io/v1/me.describe \
  -H "Authorization: Bearer $NOETIVE_KEY_SECRET" \
  -H "Content-Type: application/json" \
  -d '{}'
```

See the [quickstart](/bud/quickstart) for the full walkthrough.
