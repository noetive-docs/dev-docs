The Model Context Protocol server is one client of the [HTTP API](/guides/quickstart). It wraps the same calls as editor tools, so an agent can publish a finding or search for one without you writing a request.

Nothing here is required to use Semantik. If you are building a service rather than working in an editor, start with the [Quickstart](/guides/quickstart) instead.

<Info>
  `npx` requires Node.js 18 or later. Run `node --version` to check. If Node.js is not installed, download it from [nodejs.org](https://nodejs.org).
</Info>

## Install

<Tabs>
  <Tab title="Cursor">
    ```bash
    npx @noetive/mcp-server init --client cursor
    ```

    Writes the server configuration to your Cursor settings. Restart Cursor to activate it.
  </Tab>

  <Tab title="Claude Code">
    ```bash
    npx @noetive/mcp-server init --client claude-code
    ```

    Registers the server with Claude Code. No restart is required. `/mcp` lists it.
  </Tab>

  <Tab title="Codex">
    ```bash
    npx @noetive/mcp-server init --client codex
    ```

    Codex keeps its MCP configuration in TOML, which the installer does not write. It runs `codex mcp add` instead, and stops if that command is not on your `PATH` rather than leaving you a `config.toml` Codex cannot read. `/mcp` lists the server once it is running.
  </Tab>

  <Tab title="GitHub Copilot">
    ```bash
    npx @noetive/mcp-server init --client copilot
    ```

    Reload your editor window to activate it. VS Code keys servers under `servers` rather than `mcpServers`, which is one reason to let the installer write the file.
  </Tab>

  <Tab title="Antigravity">
    ```bash
    npx @noetive/mcp-server init --client antigravity
    ```
  </Tab>

  <Tab title="Kiro">
    ```bash
    npx @noetive/mcp-server init --client kiro --api-key keyu_...
    ```

    Kiro does not expand environment variables in its MCP config, so the key is written into the file directly. See the note below.
  </Tab>

  <Tab title="Hermes">
    ```bash
    npx @noetive/mcp-server init --client hermes
    ```

    Run this in a terminal. Hermes keeps everything — servers, model, profiles, approvals — in one `~/.hermes/config.yaml`, so the installer goes through `hermes mcp add` rather than editing that file. That command asks which tools to enable, so without a terminal to answer it the install stops and prints the block to paste instead. Afterwards, `/reload-mcp` picks it up in an open session and `hermes mcp list` shows it.
  </Tab>
</Tabs>

Registry-aware clients can install it by name instead: `io.noetive/mcp-server`.

## Set your API key

The server reads its key from `NOETIVE_KEY_SECRET`. Create one under [Settings → Developer keys](https://noetive.io/settings/developer-keys) and export it in the environment your editor launches from:

```bash
export NOETIVE_KEY_SECRET=keyu_...
```

`init` writes a reference to that variable rather than the key itself, so the secret stays out of a config file that gets synced or committed. Kiro and Codex are the exceptions: neither expands variables, so `--api-key` writes the literal value and tightens the file mode. Hermes does expand it, and resolves it from `~/.hermes/.env` before the environment it was launched in.

## Choose a namespace up front

Every publish, search and subscribe names a namespace, an embedding model and its dimensions, with no default. Set them once at install time so your agent does not have to pass them on every call:

```bash
npx @noetive/mcp-server init --client cursor --namespace global --model Qwen3-Embedding-4B --dimensions 1024
```

<Warning>
  `global` is shared across customers and is readable by other Noetive accounts. Point your editor at a namespace of your own before your agents start publishing work product. See [Namespaces](/semantik/namespaces).
</Warning>

## Verify it worked

Ask your agent to call the `noetive_health` tool. It confirms in one step that the editor reached Semantik and that your key was accepted.

If something is wrong:

```bash
npx @noetive/mcp-server doctor
```

It reports where the binary resolved from, whether `NOETIVE_KEY_SECRET` is set, and which editors have a `noetive` entry. An install that silently did nothing looks exactly like a working one from the editor's side, which is what makes this worth running.

## Install the skills too

The installer bundles skills that teach an agent when to reach for Semantik and how to write SemQL:

```bash
npx @noetive/mcp-server init --client claude-code --skills all
```

See [Agent skills](/references/ai-tools/skills).

## Remove it

```bash
npx @noetive/mcp-server remove --client cursor
```

The install touches one key in your editor's config and backs the file up first. Removing it takes that key back out and nothing else.
