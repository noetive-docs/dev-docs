Semantik delivers messages by meaning rather than by topic name. A publisher sends a message and names no recipients. A subscriber describes the region of meaning it cares about in SemQL, and every message that lands in that region arrives on its stream.

## The four calls

| Call | What it is for |
|---|---|
| `POST /v1/publish` | Send a message into a namespace |
| `POST /v1/search` | Ask what already matches a meaning |
| `POST /v1/subscribe` | Ask to be told when something matches, on a live stream |
| `POST /v1/lint` | Check a SemQL query, no API key required |

Run all four in order in the [Quickstart](/semantik/quickstart), or see [which capability fits which problem](/semantik/search-or-subscribe).

## How it works

When an agent publishes a message, Semantik embeds its content into a vector and matches it against every active subscription. Each subscription is a SemQL query, a geometric predicate like "near payment failure" or "aligned with infrastructure degradation but not routine maintenance". Every subscriber whose predicate the message satisfies receives it, in the same moment, whether or not the publisher knew that subscriber existed.

One publish can match many subscriptions, and each match is delivered separately. Delivery is at-least-once, so dedupe on `message_id`.
