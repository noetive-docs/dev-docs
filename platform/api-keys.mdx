---
title: "API keys"
description: "Developer credentials for programmatic access to Noetive."
---

API keys authenticate programmatic requests to Noetive. The MCP server uses an API key to connect your editor to Semantik on your behalf. One key reaches both Semantik and Bud. Keys begin with `keya_`.

A key acts as an **agent**. The agent decides what the key can reach: which namespaces in Semantik, and what it may do with its own mail in Bud. Each agent acts through one key at a time. You can move a key between agents or replace it without changing what the agent reaches.

Manage both at [Agents](https://www.noetive.io/dashboard/agents).

## Agents

An agent is a bot, a service or an editor that acts on your behalf.

In Semantik, an agent reaches either:

- **all your namespaces**, including ones you create later, or
- **only the namespaces you pick**.

The shared `global` namespace is a separate choice, so an agent can work entirely inside your own namespaces without touching it.

<Tip>
  Give each thing that holds a key its own agent. A leaked key then costs you that agent's reach rather than the whole account, and you can stop it without disturbing anything else.
</Tip>

Disabling an agent stops its key. Deleting an agent detaches its key and, unless you untick the option, revokes it.

If a namespace an agent was scoped to is deleted, the agent quietly reaches less than it did. The Agents page says so rather than leaving you to find out from a failing request.

### In Bud

The key reaches its agent's own mailbox in Bud. The agent's mailbox is set up on the key's first request to Bud.

Choose what each agent may use under **Mail and calendar** on its Edit access page: `mail`, `cal`, `book`, `blob`, `approve` and `freebusy`. An agent with none of them selected is refused by Bud. Reaching another agent's objects needs a grant, and access never crosses your account.

## Creating a key

<Warning>
  The full key value is shown only once, immediately after creation. Copy it before navigating away: you cannot retrieve it again.
</Warning>

From your agent's page, under **Give this agent a key**:

1. Name the key and choose an expiration: **Never**, **30 days**, **90 days**, or **1 year**.
2. Select **Create key** and copy the key immediately.

You can also select **New key** on [Agents](https://www.noetive.io/dashboard/agents) without choosing an agent. It reaches nothing until you attach it, which is useful when you want to hand out a credential before deciding what it may do.

## Attaching and detaching

An agent with no key shows **Or attach a key you already have** beside **Give this agent a key**. Pick any live key that is not attached to an agent.

**Detach** releases a key from its agent without revoking it. Anything using the key stops reaching that agent's namespaces and mailbox until you attach it again. To move a deployed key to a different agent without redeploying the secret, detach it on its agent's page, then attach it on the other agent's page.

Changes take effect within about a minute.

## Rotating a key

Select **Rotate key** on the agent's page and choose how long the current key keeps working: **1 hour**, **24 hours**, **7 days**, or **Stop it now**. The agent immediately gains a new key, which is shown once. The previous key keeps working for the period you chose, then stops, so you can deploy the new value without downtime.

The previous key is listed on the agent's page until then, with **Revoke now** if you finish early. Rotating never extends a key: one already due to expire sooner keeps its date.

## Keys with a new value

If a key under **Keys** shows **Show current value**, its format was updated. Copy the new value into whatever uses the key. The value you had keeps working until the old format is retired; if that old value may have leaked, contact support rather than relying on revoking the key.

## Revoking a key

<Warning>
  Revoking a key is irreversible. If the MCP server is using the revoked key, reconnect it with a new key.
</Warning>

Select **Revoke** next to any key under **Keys**, then **Revoke key**. New requests to both Semantik and Bud are refused within about a minute. In Semantik, subscriptions that were already open are also disconnected rather than left streaming.

To stop everything an agent can do at once, disable the agent instead. That takes effect on the same timescale and does not destroy its key, so you can turn it back on.

## Constraints

| Property | Value |
|----------|-------|
| Format | Begins with `keya_` |
| Expiration options | Never, 30 days, 90 days, 1 year |
| Display after creation | Shown once; first characters only thereafter |
| Keys per agent | One, plus the previous key during a rotation's grace period |
| Agents per key | One |
| Keys per account that are not revoked | 50 |
| Rotation grace period | 1 hour, 24 hours, 7 days, or none |
| Semantik namespaces reached | Whatever the key's agent reaches; nothing while unattached |
| Bud scopes | Chosen per agent from `mail`, `cal`, `book`, `blob`, `approve`, `freebusy` |

Store keys in environment variables or a secrets manager. Do not commit them to source control.
